PRODUCTION SECRET ROTATION CHECKLIST

The earlier source ZIPs contained local or operational credentials. Before production release, rotate or replace every value that may have been exposed:

[ ] Admin password or PIN
[ ] TV PIN
[ ] Every driver password or PIN
[ ] SESSION_SECRET (use at least 32 random bytes; rotation signs out existing sessions)
[ ] PRINT_AGENT_TOKEN and PRINT_PROXY_TOKEN
[ ] BOOTSTRAP_TOKEN or migration token
[ ] CRON_SECRET
[ ] Telegram bot token and chat credentials, if ever present in a ZIP
[ ] Stripe secret key and webhook secret, if ever present in a ZIP or message
[ ] Any Supabase service-role or database credential, if ever present in a ZIP or message
[ ] Regenerate localhost PEM/private keys instead of reusing shared copies

After rotation:

[ ] Update Vercel Production environment variables
[ ] Update the shop PC C:\Web\burger\.env.local
[ ] Update print-agent/print-proxy local configuration without committing it
[ ] Redeploy Vercel
[ ] Sign in again to Admin, TV and Driver
[ ] Test one cash order, one online order, split payment, TV logout and driver logout

DISTRIBUTED RATE LIMITING

Recommended production variables:
UPSTASH_REDIS_REST_URL=<your REST URL>
UPSTASH_REDIS_REST_TOKEN=<your REST token>
RATE_LIMIT_FAIL_CLOSED=0

Without these values, the code uses a bounded in-memory fallback. That protects a single process but is not shared across Vercel instances.
